### Observations (do not change the verdict)

1. **Write-failure notice overlaps the Feed panel.** In `s10-write-failed-notice-1280x720.png` the banner sits over the third Feed line at 1280×720. The copy is already logged as placeholder pending `/ux-design`; position is part of that.
2. **Abort and the blob.** After Abort the blob is not byte-identical to the one at mission start, but it is identical once `world` (the strategic clock) is excluded. The return to the World Network is a Screen and autosaves, so the clock moves. This run did not separate "Abort wrote nothing" from "the next Screen wrote the clock"; the unit tests for PV-005 cover the former.
3. **Telemetry setting after reload.** The harness set `telemetry: true` through `setState`; after a reload the setting read `false`. `settingsStore.ts` persists from its actions (`persist` at ~L146/222), so a `setState` probably bypasses it, but this was not verified. The Settings toggle was not exercised in the browser.
4. **Frame spike.** One 219 ms frame (and a 215 ms long task) at ~1.8 s after load, before the phase tag attached, so it is page boot, not the World Network spike (R-2). The per-phase frame data in `scenario.json` is untagged after reloads.
5. **Continue keeps the selected contract.** After reload on Debrief or mid-mission, `missionId` reads `m01` (the Screen-held selected contract). That is the GDD (Rule 7, "selected contract restores"), not a leak of the mission.
