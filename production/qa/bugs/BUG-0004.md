## Reproduction Steps
**Preconditions**: An escort mission whose objective list has an OVERRIDE (cell-lock) step before the escort step.

1. Deploy. Walk any operative to within `VIP_ACQUIRE_R` (3) of the VIP without completing the OVERRIDE objective.
2. Observe the Comm log.
3. Complete or fail to complete the override; read the objective list.

**Expected Result**: The VIP stays captive until the cell locks are overridden (`tactical-mission.md` §Extraction: "Override the cell-block locks → Walk the freed VIP to Extraction alive"). The playtest also notes the tester did not know an operative must stand at the console.
**Actual Result**: The VIP is released as soon as any agent is in range. The escort completes while objective 2 (the override) still blocks, so the mission reads as stuck.

## Notes
Not reproduced in the browser in this run; the playtest marks it code-path confirmed. Whether the escort objective should wait for OVERRIDE, or the override should be skippable, is a design call.

## Fix (2026-10-19)
- `src/game/world.ts`: new `escortLive()`; `updateVips` no longer acquires a captive VIP until an Escort objective has left `pending`. Required objectives are sequential, so on Hollow Crown the VIP stays captive until OVERRIDE THE CELL BLOCK LOCKS completes. Follows `tactical-mission.md` §16 ("Override the cell-block locks → Walk the freed VIP"); the override is not made skippable.
- `src/game/world.test.ts`: regression test "BUG-0004: the Hollow Crown vip stays captive until the cell-lock override completes". Fails without the fix, passes with it.
- Verified: `npm test` 1541/1541, `npm run lint` clean, `npm run build` OK. Live Hollow Crown on `npm run dev` (in-app browser, operative placed beside the VIP via the dev runtime): before gate and during the override, VIP `alerted=false`, no "ASSET SECURED"; after the override completes, hc3 active and "ASSET SECURED" logs. No console errors.
- Not addressed: the playtest confusion that an operative must stand at the console (no new Comm log hint was added).
