## Reproduction Steps
**Preconditions**: A campaign with Rust Haven available (intel ≥ 1).

1. Set text scale to 125 in Settings.
2. Open Rust Haven in the World Network and go to the Brief.
3. Look at the THREAT RATING box in the Contract Dossier.

**Expected Result**: The threat value and `ETA RESPONSE: < 06:00` sit side by side without touching at every text scale (TR-interface-002: nothing clips or overlaps at 90 / 100 / 110 / 125).
**Actual Result**: At 125 the `THREAT RATING` label wraps to two lines and the side column widens; `MODERATE` runs under `ETA RESPONSE: < 06:00`. At 110 the two are close but do not touch (`m03-brief-110.png`).

## Technical Context
- **Likely affected files**: `src/ui/ui.css:2049` `.mb-threat-main b { font-size: clamp(17px, 1.6vw, 24px) }`: sized from the viewport, not `--text-scale`. Its neighbours scale: `.mb-threat-main label` (:2048) and `.mb-threat-eta` (:2060) use `calc(... * var(--text-scale))`. At 125 the ETA line grows and the threat value does not shrink to make room.
- **Related systems**: Settings text scale; the Brief dossier column width
- **Possible root cause**: The threat box is a grid with `minmax(0, 1fr)` for the value column, so when the side column grows the value column shrinks below its content and the one-word value overflows under the side column.

## Evidence
- **Screenshots**: `production/qa/evidence/if-015/m03-brief-125.png` (overlap); `production/qa/evidence/if-015/m03-brief-110.png` (no overlap, little margin)
- **Test gap**: the IF-015 clip probe (`production/qa/evidence/if-015/capture.mjs:120-139`) checks only `.mb-obj` rows, `.mb-obj-kit` spans and the objectives box, so its AC4 PASS lines did not catch this. Widen the probe to `.mb-threat` when fixing.

## Fix
- **Change**: `src/ui/ui.css` `.mb-threat` is a wrapping flex row instead of a three-column grid whose middle column could shrink to 0; `.mb-threat-main` keeps its content width (`flex: 1 0 auto`) and `.mb-threat-side` stays right-aligned (`margin-left: auto`). When the value and side column do not fit on one line, the side column (blocks + ETA) drops to a second line instead of running into the value. Font sizes are unchanged.
- **Layout change**: at 1280x720 the row stays one line at text scale 90 and 100 for every rating; it wraps at 110 for MODERATE (it fit on one line at 110 before, with little margin) and at 125 for all three ratings.
- **Verified** (2026-10-22, working tree on top of `bb511e2`): `production/qa/evidence/bug-0009-fix-2026-10-22/capture.mjs`, `npm run dev` on port 4215, headless Chrome for Testing at 1280x720: **ALL PASS** (13 PASS lines). For MODERATE (Rust Haven), HIGH and SEVERE (injected generated contracts) at 90 / 100 / 110 / 125, the threat value and label intersect neither the blocks nor the ETA line, and all four sit inside `.mb-threat`. Captures viewed: `moderate-brief-125.png`, `moderate-threat-box-100.png`, `moderate-threat-box-110.png`.
- `npm run lint` clean; `npm run build` passes; `npm test` 1625/1626: the one failure is the known flaky `src/game/audio.test.ts:1088` (`audio.unlockAudio is not a function`), which also fails intermittently with this change stashed. Fixed later in e88a030 (2026-10-22): the AU-005 module-load tests moved to `src/game/audio.moduleLoad.test.ts`; `npm test` now passes 1626/1626.
