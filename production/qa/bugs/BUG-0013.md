## Reproduction Steps
**Preconditions**: A campaign that can open the Research screen.

1. Set the text scale to 100% in Settings and open Research.
2. On the reference node label (ADV.PROPELLANTS), read the computed `font-size` and multiply it by the tree SVG's `getScreenCTM().a`. The result is the rendered size.
3. Repeat at 90%, 110% and 125%.

**Expected Result**: The rendered node-label size follows the text scale up to 110% and then holds at 125%: **9.559 / 10.621 / 11.683 / 11.683 px** (±0.1) at 90 / 100 / 110 / 125.
- IF-037 AC-1 (`production/epics/interface/story-037-screen-specs-committed-tier-deltas.md:31`): "Research node labels ... follow the text scale up to 110% inside the fixed tree"

## Technical Context
- **Likely affected files**:
  - `src/ui/Research.tsx:175-179`: the `.rs-branch-svg` tree uses `viewBox` with `preserveAspectRatio="xMidYMin meet"`, so it is fitted into its column.
  - `src/ui/ui.css:3847-3852`: `.rs-node-label { font-size: calc(10.6px * min(var(--text-scale), 1.1)) }`. This works. The computed size caps correctly at 11.66 px for both 110 and 125.
- **Related systems**: Settings text scale; the Research screen layout (side columns, branch header)
- **Possible root cause**: As the text scale grows, the side columns widen and the header wraps (three lines at 125, `tc03-research-125.png`). That leaves less room for the tree column. With `meet`, the tree SVG scales down to fit (screen scale 1.010 / 1.002 / 0.968 / 0.860), so the font-size cap in user units is multiplied by a shrinking factor. The CSS cap is applied in SVG user units, while the AC and the UX spec describe the size as drawn on screen.

## Fix
**Date**: 2026-10-25. **Branch**: `worktree-agent-a1ae7994c0d9368fc` (not merged).

**Approach**: keep the tree plate from narrowing at 110 and 125% instead of compensating the font-size. Compensating by the SVG scale would have grown the labels in user units (13.56 units at 125% before the fix), and the RAIL STABILIZATION / SMART FRAGMENTATION pair has only about 1 unit between its second lines at 11.66 units, so the labels would have overlapped.

**Changes** (`src/ui/ui.css`, CSS only):
- `.rs-main`: the side columns' minimum width is no longer multiplied by the text scale: `clamp(218px, 17vw, 258px * scale)` and `clamp(286px, 25vw, 350px * scale)`. They still widen with the scale where the window has room; at 1280x720 they stay 218 / 320 px (315 px at 90%), so the tree plate keeps its 100% width (691 px) at 110 and 125%.
- `.rs-spec .kv`: wraps; a value too wide for its row (LABORATORY `BALLISTICS LAB` at 125%) drops under its label, right-aligned.
- `.rs-cols`: flex with wrap (grow 1 : 1.12, each box at least its min-content width); PREREQUISITES and PROJECTED BENEFIT stack when both no longer fit on one row.

The last two fix what the narrower right column broke at 125%: a first pass with only the column change gave 3 clips at 125% (detail list scrolling sideways 320 in 298, `BALLISTICS LAB` spill, `PREREQUISITES` spill).
