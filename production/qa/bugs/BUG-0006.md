## Notes
Design question: "Focus" (sector) and the globe's camera home are separate in code; the GDD only says Focus opens on Europe.

## Fix (2026-10-19)
- Design call (Marco Machado, 2026-10-19): the globe opens on the **Focus** sector, and HOME returns to the Focus sector. `worldStore.selected` (Focus) already opens on `eu` (`worldStore.ts:765`, `save.ts`); only the globe camera ignored it. This satisfies `world-network.md` Core Rule 5 ("Focus opens on Europe") without a second "home" point.
- `src/ui/WorldGlobe.tsx`: the camera's first position, first view command and the center readout use `SECTOR_FOCUS[selected]` captured at mount; the Focus sector outline shows from the start (`focused` starts at `selected`). The HOME button and the Home key fly to `SECTOR_FOCUS[selected]`. Removed the unused `HOME_POSITION`.
- `src/game/geography.ts`: removed `GLOBE_HOME` (`{ lat: 18, lon: -65 }`), now unused.
- Verified: `npm test` 1543/1543, `npm run lint` clean, `npm run build` OK. In-app browser on `npm run dev`:
  - New campaign, after the orientation overlay: Europe faces the camera, readout `53.00°N / 27.00°E` (`SECTOR_FOCUS.eu`).
  - Continued campaign: readout `53.00°N / 27.00°E`.
  - Focus Asia, drag the globe to `66.10°N / 176.95°W`, click HOME: `34.01°N / 103.03°E` (`SECTOR_FOCUS.as`).
  - Focus Europe, drag to `89.14°N / 36.85°W`, Home key on the globe: `53.16°N / 26.77°E`.
  - No new console errors after a reload. The only errors logged were Vite HMR reconnects from while the dev server was stopped between runs.
