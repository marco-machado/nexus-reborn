## Reproduction Steps
**Preconditions**: A campaign in progress with at least one operative in the roster (any new campaign).

1. Set text scale to 100 in Settings (contrast default; repeat with high contrast).
2. Open Assembly from the shared nav.
3. Look at the four stat tiles in the right dossier column: `HLTH`, `STAMINA`, `FOCUS`, `MOBILITY`.
4. Repeat at text scale 110 and 125, then at 90.

**Expected Result**: Every stat tile label sits on one line at every text scale (IF-036 AC-2: nothing clips, truncates or spills; owner ruling 2026-10-24: a mid-word break is a defect).
**Actual Result**: At 100, 110 and 125 the `MOBILITY` label renders as 2 line boxes, `MOBILIT` / `Y`. Measured label width and font size: 49.6 px at 10 px (100), 52.5 px at 11 px (110), 62.9 px at 12.5 px (125). At 90 it is 1 line (49.6 px at 9 px). `HLTH`, `STAMINA` and `FOCUS` stay on one line at every scale. Same in default and high contrast.

## Technical Context
- **Likely affected files**: `src/ui/ui.css:2471` `.ts-stats label { font-size: calc(10px * var(--text-scale)); color: var(--ink); letter-spacing: 0.04em; overflow-wrap: anywhere; }`. The tile is narrower than the 8-character label at 10 px and up, and `overflow-wrap: anywhere` lets the browser break inside the word instead of overflowing or wrapping at a word boundary.
- **Related systems**: Settings text scale; the Assembly dossier column width and stat tile grid (`.ts-stats`)
- **Possible root cause**: The stat tile width (approx. 50 px, `design/ux/assembly.md` width table line 419) does not fit `MOBILITY` at 10 px with 0.04 em letter-spacing, and a single word has no break opportunity other than the one `overflow-wrap: anywhere` creates mid-word.

## Fix
**Date**: 2026-10-25 (owner decision: give the tiles room)
**Change**: the four stat tiles are a 2 by 2 grid instead of four across (`.ts-stats { grid-template-columns: repeat(2, minmax(0, 1fr)) }`), so each tile is about half the dossier column (119 px inner at 90/100%, 125 at 110%, 146 at 125%) instead of about 50 px. `overflow-wrap: anywhere` is removed from `.ts-stats label`; it is no longer needed. Label copy unchanged; no truncation or ellipsis. The stat block grows by one row; the dossier list still scrolls (P-15).
**Files**: `src/ui/ui.css` (`.ts-stats`, `.ts-stats label`); `design/ux/assembly.md` (Open Question 15 Closed; text-scale row in Accessibility).
**Verification** (`production/qa/evidence/bug-0011-fix-2026-10-25/`, headless Chrome for Testing, 1280x720, dev server port 4312):
- `npx vitest run`: 68 files, 1668 tests passed. `npm run lint`: clean. `npm run build`: succeeded.
- TC-036-22 re-walk (`linebox.mjs`): `Range.getClientRects()` line boxes for `HLTH` / `STAMINA` / `FOCUS` / `MOBILITY` = 1 / 1 / 1 / 1 at 90, 100, 110 and 125, default and high contrast; no label overflows its tile. `MOBILITY` 46.2 / 51.4 / 56.5 / 64.2 px wide in a 119 / 119 / 125 / 146 px tile.
- Team sweep (`screens-2026-10-23/sweep.mjs`, `SURFACES=team`): every count 0 (sub-10 px, contrast default and high contrast, Ink Dim/Faint, label-in-name, targets <24, clip at 90/100/110/125).
- Dossier list scrolls at every scale (`.ts-detail-list` client height under scroll height).
- Test gap closed for this label: `linebox.mjs` is the line-box check the Evidence section asked for. It is not yet folded into `sweep.mjs`.
- Not checked: other resolutions; +40% localized labels.
