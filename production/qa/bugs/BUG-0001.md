## Reproduction Steps
**Preconditions**: A live Glass Veil (m01) mission on Standard, with no result, not paused, on a fresh campaign.

1. Press Escape. The pause modal ("Mission paused") opens.
2. Activate "Open settings". The Settings dialog opens, and the game stays paused.
3. Press Tab until the MASTER volume slider (`input[type=range]`, value 100) has focus.
4. Press Space.
5. Wait 1 s, then check the pause state, the open dialogs, the sim time and the focused element.

**Expected Result**: The mission stays paused, Settings stays open, the sim time does not change, and focus stays inside Settings. This is IF-008 AC11: "Settings opened from pause stays inside the freeze".

**Actual Result** (1 s after Space):
- `paused` goes from `true` to `false`.
- The Settings dialog unmounts. Open dialogs go from `["Settings"]` to `[]`.
- The sim time goes from 6.261 to 7.279, so the mission runs while the player believed it was frozen.
- Focus moves to the HUD control "Pause and open the menu".
- There are 0 console errors and 0 page errors.

**Scope tested**: Only the MASTER slider. The UI CUES, COMBAT, MUSIC and AMBIENCE sliders are the same element type, but they are **not verified**.

## Technical Context
- **Likely affected files**:
  - `src/scene/Input.tsx:128`: the Space exemption returns early only when `document.activeElement` is an `HTMLButtonElement` inside `[role="dialog"]`.
  - `src/scene/Input.tsx:148-149`: `case 'pause': ms.setPaused(!ms.paused)`. A focused `input[type=range]` inside Settings misses the exemption and lands here.
  - `src/ui/PauseMenu.tsx`: renders Settings only while the mission is paused, so the unpause also unmounts Settings.
  - `src/ui/Settings.tsx:65`: the volume `input type=range` elements. This line number comes from IF-008 review advisory 4 and was not re-checked in this run.
- **Related systems**: Mission state (`useMissionStore` `paused`), the pause menu, Settings, and keyboard bindings (Settings lists PAUSE MENU as SPACE / ESC, FIXED).
- **Possible root cause** (from a code read, not a confirmed fix): the Space guard at `Input.tsx:128` treats only buttons as dialog controls that own Space. Other focusable form controls inside a dialog pass through to the global `pause` toggle.
- **Suggested fix direction** (for the programmer to decide):
  - Option 1: widen the guard so that any focused form control inside a `[role="dialog"]` owns Space.
  - Option 2: ignore Space for `pause` while any dialog other than the pause modal is mounted.
  - Either way, add a regression test that covers Space with a range input focused inside Settings opened from pause.

## Fix
- **Date**: 2026-10-19, on `main` after `ae38bd9`.
- **Change**: Option 1. `src/ui/pauseMenuModel.ts` adds `dialogControlOwnsKey(code, focus)`: Space is owned by any focused `BUTTON`, `INPUT`, `SELECT` or `TEXTAREA` inside a `[role="dialog"]`. Escape is never owned. `src/scene/Input.tsx` calls it in place of the button-only guard, so Space on a Settings slider never reaches the `pause` toggle.
- **Regression test**: `src/ui/abortArm.test.ts`, "BUG-0001: Space on a focused Settings slider, opened from pause, keeps the freeze". It also covers a dialog button still owning Space, Escape never owned, and Space with no dialog control still toggling.
- **Verified**:
  - `npx vitest run`: 60 files, 1539 tests pass. `npm run lint` clean. `npm run build` succeeds.
  - Probe re-run against `npm run dev` (port 4200), headless Chrome for Testing at 1280x720: `production/qa/evidence/bug-0001-fix-2026-10-19/probe.mjs` (a copy of the team-qa probe with TC-06 extended to every slider). Output in `probe-run.log` and `probe-output.txt` there: **ALL PASS**, 0 console or page errors. TC-01, TC-04 and TC-05 pass. TC-06 passes on all five sliders (MASTER, UI CUES, COMBAT, MUSIC, AMBIENCE): still paused, Settings mounted, sim time 6.15 unchanged, focus unchanged. Space on the live mission after closing Settings and resuming still opens pause.
  - `probe-06b-after-space.png`: Settings still open, badge reads "PAUSED".
  - Dialog-button exemption, in the Claude desktop in-app browser against `npm run dev` (port 4200): fresh campaign, live Glass Veil mission (reached through the app store, the same harness assist as the probe), Escape, "Open settings", Tab ×6 to the MUTE button ("MUTE // OFF"), Space. Result: MUTE went to "MUTE // ON", `paused` stayed `true`, Settings stayed open, sim time stayed at 0.167, focus stayed on MUTE. A second Space put MUTE back to OFF, again with no change to pause. Console: only Vite HMR `WebSocket connection to 'ws://localhost:4200/' failed` errors, no app errors.
