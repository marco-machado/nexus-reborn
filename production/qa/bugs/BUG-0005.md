## Reproduction Steps
**Preconditions**: Several operatives selected, grenade targeting on, and the first id in the selection unable to throw at the target.

1. Select several operatives.
2. Arm the grenade (Q) and click a target point.
3. Watch the squad and the Comm log.

**Expected Result**: Per `tactical-mission.md` Core Rule 6, Q "fires actives of the **current selection**". An empty or invalid item use reports on the Comm log and spends nothing.
**Actual Result**: Only `ids[0]` is ordered. If it fails, `orderGrenade` returns false, targeting stays armed, and no message appears.

## Fix (2026-10-19)
- `src/game/world.ts`: `orderGrenade` takes the selection (`agentIds: string[]`, like `orderUseCell` / `orderUseMed`). The first living selected operative within `GRENADE_RANGE` throws. A throw nobody can make pushes one Comm log line and spends nothing: `GRENADE: NO LIVING OPERATIVE SELECTED.`, `GRENADE: NO OPEN GROUND AT THE TARGET.` (off map, or no pavement within 2.5 m), `GRENADE: TARGET OUT OF RANGE OF THE SELECTION.`. Empty cells, the squad cooldown, and a non-live/paused mission stay silent (Core Rule 6: those disable the control). The now-unused `canUseAbility` was removed. Follows `tactical-mission.md` Core Rule 6.
- `src/game/types.ts` (CONTRACT FILE): `WorldApi.orderGrenade(agentIds: string[], target)`, with a comment on the fail lines.
- `src/scene/Input.tsx`: the click handler passes the whole selection, not `ids[0]`. On failure targeting stays armed so the player can pick another point.
- Tests: two BUG-0005 regression tests in `src/game/world.test.ts` (out-of-range first id, in-range second id throws; each fail line logs and spends nothing). Existing callers in `world.test.ts` and `audio.stings.test.ts` moved to the array form.
- Docs: `docs/architecture/architecture.md` (WorldApi listing), `docs/mission-playbook.md` (order table).
- Verified: `npm test` 1543/1543, `npm run lint` clean, `npm run build` OK. Mutation (throw only if `crew[0]` is in range) fails the multi-select test; restored. Live Glass Veil on `npm run dev` (in-app browser): a1 walked to 28.7 m from the squad through `orderMove`; with the opening all-four selection (a1 first), G + a real click beside the squad threw, `GRENADE DETONATED. CELL EXPENDED.`, cells 1 → 0. Redeployed, `1` selects a1 only, G + same click: Comm log panel shows `GRENADE: TARGET OUT OF RANGE OF THE SELECTION.`, cells stay 1, targeting stays armed.
- Not addressed: grenade damage feeling low (balance note, see Notes).
