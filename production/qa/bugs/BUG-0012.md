# Bug Report

## Summary
**Title**: World Network: CAMPAIGN FAILED banner always reads `0 / 3` (count hardcoded, ignores contracts won)
**ID**: BUG-0012
**Severity**: S3-Medium
**Priority**: P3-Backlog
**Status**: Open
**Reported**: 2026-10-24
**Reporter**: /team-qa sprint manual QA (IF-016-04 variant B)

> Severity and priority are proposed by `/bug-report`: the count is wrong information on an end-of-campaign status record, but it appears only after a lost campaign, blocks nothing, and the rest of the banner is correct. `/bug-triage` sets the final value.

## Classification
- **Category**: UI
- **System**: Interface: World Network (campaign banner, ADR-0020 / Interface Rule 18)
- **Frequency**: Always (deterministic: any failed campaign with one or more authored contracts won)
- **Regression**: No. Pre-existing; IF-016 (`05c7bd7`) changed only the failed banner's `<i>` line and was told to leave the count unchanged. The `<strong>0 / {MISSIONS.length}</strong>` line is a context line in its diff (`05c7bd7-WorldMap.diff`).

## Environment
- **Build**: `131a5c1` (HEAD, Sprint 11)
- **Platform**: headless Chrome for Testing via playwright-core, 1280×720
- **Scene/Level**: World Network
- **Game State**: Campaign failed after one authored contract won: store `{"ops":0,"won":["m01"],"failed":true,"complete":false}`

## Reproduction Steps
**Preconditions**: A new campaign; orientation card dismissed.

1. Take Rust Haven (m01) and win it; report it through the Debrief (`reportMission`).
2. Take the next authored contract (m02) and lose the whole roster; report it through the Debrief (`reportMission`), which empties the roster and sets the campaign failed.
3. Return to the World Network and read the CAMPAIGN FAILED banner's count.

**Expected Result**: The banner's count reads `n / 3` with n = authored contracts won (`design/ux/world-network.md:157`, Banner row: "`CAMPAIGN COMPLETE` or `CAMPAIGN FAILED`, sigil, secondary line, `n / 3` count"). Here: `1 / 3`. The CAMPAIGN COMPLETE banner already counts wins (`{contractsWon.length} / {MISSIONS.length}`).
**Actual Result**: The count reads `0 / 3`.

## Technical Context
- **Likely affected files**: `src/ui/WorldMap.tsx:856` `<strong>0 / {MISSIONS.length}</strong>` in the `banner === 'failed'` block. The complete banner's count (`WorldMap.tsx:866`) uses `contractsWon.length`.
- **Related systems**: campaign fail flags (`docs/architecture/adr-0020-campaign-fail-flags.md`); `reportMission` / Debrief path that records wins and sets the failed flag
- **Possible root cause**: the failed count was written as a literal `0`, presumably on the assumption that a failed campaign has no wins; a campaign can fail after one or two authored wins.
