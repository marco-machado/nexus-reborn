## Notes

1. **Harness defect, R1 fixture (not a product fail).** At HEAD the dev server serves `/src/state/tutorialStore.ts?t=1792893423482` and `/src/game/tutorial.ts?t=1792893423482` (an HMR timestamp, read from the page's resource entries). `appStore`, `campaignStore` and `worldStore` load without `?t=`. The probe's `dismissCard()` imports the bare `/src/state/tutorialStore.ts`, which gets a second store instance. A diagnostic run showed `seen=["hint-worldmap"]` on that instance while `.wm-onboard-wrap` stayed up for 6 s. As a result, the R1 HEAD capture `../r1-probe/if-016-017-failed.png` shows the WORLD NETWORK // ORIENTATION card over the screen. R1's IF-017 text checks read row DOM, so they hold. Its forced click hit the row, which the card does not cover at x≈1110. IF-017-06 repeated that click with a valid fixture. **Any R1/R2/R4 result that assumes the card is dismissed (`opening` and every state built on it) should be re-checked by qa-lead.** `walk.mjs` works around this by importing the URL the app loaded. No `src/` or existing script was edited.
2. **Marker tooltip does not show on hover (observation, outside IF-017's ACs; spec not checked).** On the hovered GLASS VEIL marker, `:hover` matched, and `.tip` computed `display:flex; visibility:visible; opacity:0`. `.tip` sets `opacity: 0` (`src/ui/ui.css:358-377`). The `opacity: 1` rule exists only for `.wm-marker:hover .tip` (`:1258`). `.globe-marker:hover .tip` (`:4541`) sets display and position but not opacity, and the marker has no `.wm-marker` ancestor. So `if-017-failed-marker-tip.png` shows no tooltip. The tooltip's DOM text reads `CAMPAIGN LOST`, which is what AC-1 checks. Step 3's "tooltip showing" capture could not be met. Refer to qa-lead to judge against the globe/WN UX spec before filing.
3. The globe's always-on marker labels read `NEW CARTHAGE · LOCKED`, `SHINGANG · LOCKED` and `DETROIT SPRAWL · LOCKED` in the failed state. They show no cause. That is the city label, not the row/marker cause the story covers. Recorded only.
4. Script fixes made during the run (the app was not touched): the HMR store URL (Note 1). Real clicks go through `page.mouse.click`, because Playwright's `locator.click` refuses `aria-disabled` elements ("element is not enabled"). The generated row is scrolled into view before its capture.
5. The fixture held one generated row (NEON GARDEN, eu) and no PRIORITY row.
